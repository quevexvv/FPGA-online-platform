# Реестр рисков

| ID | Описание риска | Решение |
|:---|:---|:---|
| **R01** | **Долгая сборка Quartus.** Студент думает, что сайт завис, и обновляет страницу, прерывая сессию. | 1. Честное отображение стадий на фронтенде.<br>2. Сборка в `systemd`, не зависит от браузера. |
| **R02** | **Уязвимость безопасности.** Студенческий манифест пытается выйти за пределы `runs/<run_id>` или подменить QSF/SDC шаблоны. | 1. Валидация `manifest.json` через `jq`.<br>2. Запрет `../`, абсолютных путей и симлинков. |
| **R03** | **Обрыв сети (SSH/SFTP) во время выполнения.** Связь между Бэкендом и Стендом пропадает во время сборки или прошивки. | 1. `systemd` с `linger` и `Restart=no`.<br>2. Идемпотентность: повторный `submit` возвращает `existing`. |
| **R04** | **Единая точка отказа (SPOF).** Одна плата C5G — если зависнет, демо невозможно. | 1. Логика `busy` и кулдаун 5-10 минут.<br>2. Принудительное убийство процессов по таймауту. |
| **R05** | **Остаточные данные в буфере UART.** FT232R может содержать "мусор" от предыдущего запуска. | Очистка буфера UART и сброс обёртки перед новым сеансом. |
| **R06** | **Утечка скрытых тестов или эталонов.** Бэкенд может передать `expected_dout` скрытых проверок через API. | Разделение данных на стороне бэкенда. В `result.json` для студента — только открытые векторы. |
| **R07** | **Зависание процесса Quartus CLI.** Quartus может игнорировать SIGTERM при ошибках HDL. | Принудительное завершение всего дерева процессов (`kill -9`) по таймауту. |
| **R08** | **Ошибочное отображение `hardware_verified: true` для mock.** Фронтенд может показать "галочку" для демонстрационного режима. | Жёсткая проверка на бэкенде: если `mode == "mock"`, принудительно `hardware_verified = false`. |
| **R09** | **Переполнение диска файлами `work/`.** При сбоях или ошибках `cleanup` файлы Quartus заполнят 65 ГБ. | Вывод сообщения о нехватке места.|
