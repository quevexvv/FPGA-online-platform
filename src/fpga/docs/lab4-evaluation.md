# Аппаратный сценарий ЛР4

Пилот варианта А использует цифры и UART 115200 8E1. Ввод сразу
отображается в консоли и записывается в семь 16-битных слов внешней SRAM
с адреса 0. До Enter на HEX остаётся предыдущая строка. Enter читает
новую строку из SRAM, обновляет HEX и отправляет в консоль
`ESC[2J ESC[H`. Следующая строка перезаписывает память с адреса 0.
При длине больше четырёх цифр окно движется вперёд и назад.
Кадр с неверной чётностью даёт `%` и не меняет память.

Из `src/fpga` соберите доверенный проект. Подключите USB-Blaster и UART
одновременно. Для HEX2/HEX3 освободите 40-контактный GPIO и проверьте
положение S1/S2 по [инструкции ЛР3](lab3-evaluation.md#плата-и-запуск).

```bash
make all test-lab4-evaluation build-lab4-evaluation
bin/fpga-dispatch lab4-demo "$cable" "$device_index" "$uart_device"
```

Имя кабеля и индекс берутся из `jtagconfig`. Команда держит блокировку
стенда на протяжении прошивки, UART и JTAG. Она проверяет пустые HEX после
прошивки, эхо и parity, затем состояния до и после Enter для строк
`1234` и `9876`. Отчёт JSON содержит вердикт и прочитанные кадры с
ожидаемыми значениями. Сегменты кодируются так же, как в
[трассе ЛР3](display-observations.md#индикаторы-пилота-лр3).

При расхождении возвращается `mismatch` и имя фазы. При отказе JTAG или
UART возвращается `board_error` с уже полученными кадрами. Сценарий
запускается оператором через отдельную команду диспетчера. Обычные
`submit/status/cleanup` обслуживают пакетные задания по своему контракту.

На C5G все пять кадров совпали. При остановленной передаче результата
от диагностической фикстуры helper UART вышел по таймауту, отчёт сохранил
кадр после прошивки. После загрузки штатного проекта полный сценарий
повторно вернул `passed`. Симуляция с подменой слова непосредственно в
модели SRAM подтвердила чтение с шины и проверила движение окна.
