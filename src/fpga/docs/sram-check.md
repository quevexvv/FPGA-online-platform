# Проверка внешней SRAM C5G

Доверенный проект проверяет асинхронную SRAM 256K×16. Адреса обозначают
16-битные слова. Привязка контактов и активный ноль управляющих сигналов
взяты из [руководства C5G, таблица 3-10](https://www.unikeyic.com/media/datasheet/upload/2021/05/20/C5G.pdf).
Тайминги устройства описаны в [даташите ISSI](https://datasheet.lcsc.com/datasheet/pdf/ab086c9663d66c1917e2a17a2e8a61a8.pdf?productCode=C883296).

Контроллер на 50 МГц выделяет 60 нс на установку, 100 нс на чтение
или импульс записи и 60 нс на удержание и освобождение шины.
При чтении DQ управляет SRAM, при записи — ПЛИС с отключённым OE.
Оба байта активны. SDC задаёт ограничения для направлений ввода и вывода
DQ, адреса и управляющих сигналов.

Из `src/fpga` соберите и запустите проверку. Имя кабеля и индекс
устройства возьмите из `jtagconfig`.

```bash
make test-sram-check build-sram-check
bash scripts/jtag-observe.sh program-sram-check "$cable" "$device_index"
bash scripts/jtag-observe.sh sram-check "$cable" "$device_index"
```

Первый запрос по JTAG начинает тест после перехода ПЛИС в рабочий режим.
Проект записывает четыре шаблона по адресам `00000`, `00001`, `20000` и
`3ffff`, читает их, перезаписывает второе слово и повторяет чтение.
Ожидаемый результат — `passed` и восемь слов
`55aa 1248 a55a e817 55aa 6996 a55a e817`. Иное слово даёт `mismatch`,
а отсутствие подтверждённого JTAG-снимка завершает команду с ошибкой.
Сценарий изменяет эти четыре слова внешней SRAM.

На C5G все восемь слов совпали, результат повторно прочитан отдельным
сеансом JTAG. TimeQuest проверил 32 ограничения с минимальным запасом
0,149 нс и TNS=0. Без задержек внешних портов остались только
зарезервированные линии JTAG TDI, TMS и TDO.

## SRAM helper пилота ЛР4

Входы `clk`, `request`, `write_word`, `address[17:0]` и `data_in[15:0]`
задают операцию на фронте 50 МГц. Импульс `request` подаётся при низком
`busy`. Единица в `write_word` означает запись. Helper держит `busy`
до завершения операции, после чтения значение доступно в `data_out[15:0]`.

На стороне памяти helper выдаёт один импульс `mem_request` с
`mem_write`, `mem_address[17:0]` и `mem_data[15:0]`. Доверенный
контроллер отвечает `mem_done` и возвращает результат чтения в
`mem_result[15:0]`. Так сохраняется схема `request/busy`, а разрядности
соответствуют C5G. Направлением DQ и физическими сигналами CE/OE/WE
управляет контроллер платформы.

```bash
make test-sram-helper-check build-sram-helper-check
bash scripts/jtag-observe.sh program-sram-helper-check "$cable" "$device_index"
bash scripts/jtag-observe.sh sram-check "$cable" "$device_index"
```

В доверенном проекте можно подставить HDL с модулем `student_sram_helper`
через `LAB4_HELPER`. Сборки этого проекта выполняются последовательно.
Стенд проверяет чтения helper после доверенных записей и доверенное
чтение после записи helper. На запрос разрешена одна операция в четырёх
диагностических адресах. Неполное чтение по истечении 64 тактов даёт
`mismatch` с доступными словами.

На C5G исправная фикстура дала `passed`. Фикстура, подменяющая
`20000` на `00000`, дала `mismatch` со значением `55aa` вместо
`a55a`. Симуляция дополнительно обнаружила изменение записываемых данных.
