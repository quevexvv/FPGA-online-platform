# Логические состояния LED и HEX на C5G

Бэкенд может преобразовать доступные пользователю наблюдения для
отображения платы. Значения описывают логические сигналы, физическое
свечение проверяется отдельно. Версия и формат исходных отчётов — [1](file-contract.md).
Команды выполняются из `src/fpga`.

## Светодиоды MVP

```sh
jq --arg source led -f scripts/display-observations.jq examples/result-mock.json
```

| Поле представления | Значения | Порядок элементов |
|---|---|---|
| `observations[].red` | 10 логических значений, `true` включает LED | LEDR0–LEDR9 из `dout[0..9]` |
| `observations[].green` | 8 логических значений, `true` включает LED | LEDG0–LEDG7 из `dout[10..17]` |

`dout=0x00003` включает LEDR0 и LEDR1. Для изображения используется весь
`dout`. `mask` применяется только при оценивании. Каждая запись сохраняет
`vector_index`, включая частичные наблюдения при ошибке. `mode=mock`
помечает демо, а `hardware_verified` сообщает, получен ли полный набор
аппаратных наблюдений. Пустой список означает отсутствие снимков.

## Индикаторы пилота ЛР3

Для команды `lab3-trace` используйте имя кабеля и индекс из `jtagconfig`.
Подготовка платы описана в [инструкции ЛР3](lab3-evaluation.md).

```sh
bash scripts/jtag-observe.sh lab3-trace "$cable" "$device_index" | \
  jq --arg source lab3 -f scripts/display-observations.jq
```

`current` — один кадр, `before` и `after` — серии кадров до и после
ошибочного UART-байта. Каждый кадр представлен четырьмя числами в порядке
`[HEX0, HEX1, HEX2, HEX3]`. На панели C5G слева направо расположены
HEX3–HEX0. Биты 0–6 каждой маски обозначают сегменты `a`–`g` (верхний,
верхний правый, нижний правый, нижний, нижний левый, верхний левый,
средний). Единица включает сегмент. Инверсия контактов учтена в HDL.
Например, маски `[102,79,91,6]` дают `1234` слева направо, а `[0,0,0,0]`
гасит все индикаторы. Трасса ЛР3 не содержит итоговый вердикт и поля MVP.
