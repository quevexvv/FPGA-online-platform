# С чего начать

FPGA-часть должна собирать проект, загружать его на плату, запускать проверку
и возвращать результат бэкенду. Готовы проверки оборудования, форматы
обмена, подготовка, регистрация и аппаратный сценарий задания.

Уже проверены светодиоды платы и генератор, который выдаёт заданное число
тактов. C-транспорт UART проверен через псевдотерминал. Полная служебная
обёртка прошла симуляцию, сборку Quartus и проверку UART на плате для двух
учебных примеров. Приёмка STEP N описана в [документации обёртки](uart-hdl.md).
Команды протокола доступны в `build/fpga-uart`.

Все команды ниже выполняются из каталога `src/fpga`:

```sh
make all       # Собрать C-проверки и проверить синтаксис скриптов
make test      # Проверить CLI, регистрацию заданий, JSON и UART
make test-hdl  # Проверить HDL в симуляторе, без платы
make lint      # Проверить shell-скрипты и C
```

Для этих проверок нужны Bash, Make, jq, ShellCheck, Icarus Verilog и flock.
Quartus нужен для сборки прошивки, плата — для аппаратной проверки.
Примеры сборки и загрузки приведены в описаниях экспериментов.

## Регистрация задания

Оператор задаёт `FPGA_JOBS_ROOT` с абсолютным путём к каталогу стенда.
`incoming` и `runs` размещаются на одном разделе. Бэкенд завершает
загрузку `incoming/<run_id>` перед `submit` и закрывает все файлы задания.
Диспетчер возвращает `accepted` после публикации исходников, рабочего
проекта и `status.json` со статусом `starting`. `status --run-id <uuid>`
возвращает сохранённый статус. Повтор с тем же режимом возвращает
`existing`, смена режима и замена входа отклоняются.

Загрузка содержит один `manifest.json` и перечисленные в нём файлы
Verilog-2001. Диспетчер отклоняет ссылки, лишние файлы, директиву
`include` и загрузку внешней памяти через `$readmemh`/`$readmemb`.
Для проверки портов используется элаборация Icarus без симуляции.
Встроенные наборы `counter-v1` и `combinational-v1` находятся в
`testsets/`. Ошибка входа до публикации возвращает `invalid_input` в
stderr и код 2, загрузка остаётся доступной для исправления.

## Запуск на стенде

После регистрации `fpga-dispatch submit` запускает пользовательский сервис
`fpga-run-<run_id>.service`. Повторный `submit` возвращает `existing`.
Если стенд занят, задание получает `busy`. Если systemd не запустил сервис,
задание получает `internal_error` с кодом `service_start_failed`.

Подготовьте хост под отдельной учётной записью оператора. Запустите
`make all`, создайте `incoming/` в корне заданий и включите для этой
учётной записи `loginctl enable-linger <пользователь>`. Так user manager
останется доступным после выхода. Вызывайте диспетчер от этой учётной записи
с доступом к её пользовательской шине systemd. Для диагностики сервиса
используйте `journalctl --user -u fpga-run-<run_id>.service`.

Для ручной диагностики задайте `FPGA_DISPATCH_LAUNCH=manual` перед `submit`
и запустите `fpga-run` из учётной записи оператора. Бэкенд вызывает
`fpga-dispatch`.

Для режима `hardware` укажите в `FPGA_RUN_CONFIG` путь к своей копии
`config/integration.example.json`. В ней задаются пути к Quartus и UART,
имя кабеля USB-Blaster, номер устройства в цепочке JTAG и лимиты этапов.
Для ручной проверки используйте доверенный пример.

Исполнитель собирает новый `job.sof`, загружает его в SRAM платы и
проверяет ответы UART перед тестом. USB-Blaster и UART удобнее подключить
одновременно. При одном кабеле его можно переставить в UART после загрузки,
пока идёт ожидание порта в пределах `uart_ready_timeout_ms`.

Каждый вектор даёт один снимок, который сравнивается с эталоном по маске.
Результат и журналы находятся в `output/`. При обрыве связи сохраняются
уже полученные снимки и результат `board_error`.

Режим `mock` поддерживает модели `counter-v1` и `combinational-v1`, а
`mock-uart-error-v1` имитирует таймаут UART. Выбор задаётся через `test_set`
в манифесте. Mock возвращает `hardware_verified: false` и работает без платы
и Quartus.
