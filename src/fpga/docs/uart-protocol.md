# Служебный UART v1

Формат для будущей обёртки: **115200 baud, 8 data bits, no parity, 1 stop bit**,
без flow control, idle HIGH. UART студента сюда не входит. При 50 МГц
делитель RX/TX и его ошибку нужно проверить при реализации HDL.
Clock-кандидат: 1 МГц, отдельная reset-команда — 2 импульса.

Команды — ровно 7 ASCII-байтов: `1`, opcode, 4 строчные hex-цифры, LF (0x0a).
Ответы — ровно 8 байтов: `1`, type, 5 строчных hex-цифр, LF.
CRLF, пробелы и верхний регистр hex не допускаются. Многобайтовых чисел нет:
старшая hex-цифра идёт первой. Передача не содержит терминального NUL.

| Команда (показан LF как `\n`) | Действие | Ответ после завершения |
|---|---|---|
| `1R0000\n` | Reset=1, 2 импульса, остановка, выдержка, reset=0 | `1K00000\n` |
| `1I03ff\n` | Зафиксировать din[9:0], clock остановлен | `1K00000\n` |
| `1S0003\n` | Ровно 3 полных импульса, затем остановка и выдержка | `1K00000\n` |
| `1S0000\n` | Ни одного фронта, дождаться стабильного снимка | `1K00000\n` |
| `1Q0000\n` | Прочитать весь стабильный dout[17:0] | `1D00003\n` (пример) |

R и Q требуют нулевой payload. I: 0000..03ff (10 бит), S: 0000..ffff
(16 бит). D: 00000..3ffff (18 бит). Ширина поля S — максимум кодирования,
не разрешённый эксплуатационный лимит: лимиты задания/общего времени будут
выбраны отдельно после измерений. Reset не меняет din, его 2 такта не входят
в steps. Входы удерживаются от I до следующей I, включая всю пачку.
K отправляется после полного последнего импульса и низкой выдержки 25 sys_clk
(500 нс). После R сначала снимается reset, затем отправляется K.
Снимок захватывается целиком после остановки; побитовая синхронизация запрещена.

Один запрос в работе, один ответ; хост ждёт полный ответ перед следующей
командой. Во время выполнения новая команда отклоняется busy без воздействия.
Нет автоматического повтора R/I/S при потерянном ответе: состояние неизвестно,
сеанс завершается board_error; новый запуск требует нового run_id.

Ошибки имеют вид `1E0000c\n`:

| c | Причина |
|---|---|
| 1 | Неподдерживаемая версия |
| 2 | Неверная длина/символ/формат |
| 3 | Неизвестный opcode |
| 4 | Выход за разрядность или ненулевой reserved payload |
| 5 | Busy, команда не исполнена |
| 6 | Ошибка UART framing, команда не исполнена |

Проверка кадра до любого воздействия: длина → версия → opcode → hex →
разрядность/reserved → busy. Максимум буфера приёма: 6 байтов без LF.
На 7-м байте без LF перейти в discard до LF, затем вернуть E2 один раз.
Оборванный кадр без LF не исполняется и не подтверждается. По таймауту
приёмник сбрасывает накопленный фрагмент; хост считает отсутствие ответа
ошибкой, не успехом. UART framing error также сбрасывает фрагмент и требует
discard до LF; E6 отвечает один раз, никаких частичных воздействий.
Длительности межбайтового/операционного/общего таймаутов пока открыты,
ограниченность ожидания обязательна. CRC и восстановление сеанса не реализованы;
протокол предназначен для локального доверенного USB-UART, не защиты от помех.

Пример полного обмена счётчика: R0000 → K00000, I0001 → K00000,
S0003 → K00000, Q0000 → D00003 (каждый кадр с префиксом `1` и LF).
Только S даёт 3 рабочих такта; R даёт ещё 2 reset-такта отдельно.
`make test-protocol` проверяет табличные кадры; это проверка спецификации,
а не реализация UART, C-транспорта или HDL-декодера.
