# API каталога лабораторных

Реализованы список и карточка лабораторной. Хранение локально — SQLite,
миграция `0003_create_labs` применяется при старте приложения.
Миграция создаёт только таблицу, без демонстрационных данных.

## Доступ

Оба маршрута требуют действующей cookie-сессии `fpga_session` после `/auth/login`.
Без сессии, с истёкшей сессией или неактивным пользователем ответ — `401`.
Браузерный клиент передаёт cookie через `credentials: "include"`.
CSRF-токен для этих GET-запросов не требуется.

Временное правило этапа 1: все активные вошедшие студенты и преподаватели
видят весь опубликованный каталог. Неопубликованные записи отсутствуют
в списке и возвращают `404` по ID для обеих ролей. Это не индивидуальное
назначение лабораторной: группы, сроки и права на назначения — следующий этап.
Правило доступа нужно согласовать с командой до пилота.

## Маршруты

| Запрос | Результат |
| --- | --- |
| `GET /labs?limit=20&offset=0` | `200`, массив кратких карточек; пустой каталог — `[]` |
| `GET /labs/{lab_id}` | `200`, полная карточка |
| Существующая сессия, отсутствующая или неопубликованная работа | `404`, `{"detail":"Laboratory not found"}` |
| Некорректный UUID или параметры страницы | `422` |

`limit`: 1–100, по умолчанию 20. `offset`: неотрицательный, по умолчанию 0.
Сортировка: название, затем UUID. Последующая страница определяется увеличением
offset; пустой массив означает конец списка. GET не изменяет каталог.

Краткая карточка содержит только `id`, `title`, `description`, `kind`, `is_demo`.
Полная дополнительно содержит `statement`, `template`, `interface_description`.
`kind` — `combinational` или `sequential`. `is_demo` отмечает тестовый учебный
материал и не является результатом запуска в режиме mock.
Условие и описание — обычный текст; фронтенд не должен исполнять их как HTML.

Ответы используют явные схемы полей. Тестовые наборы стенда, скрытые векторы,
эталонный код и пути файлов в API не передаются. Статус выполнения и дедлайн
пока не возвращаются: для них нужны попытки и назначения. Swagger: `/docs`.

## Локальный учебный пример

Из `src/backend` с активным виртуальным окружением:

```bash
DATABASE_URL=sqlite:///./fpga-local.sqlite3 python -m app.modules.labs.seed
DATABASE_URL=sqlite:///./fpga-local.sqlite3 uvicorn app.main:app --reload
```

Команда создаёт одну опубликованную демонстрационную работу с ID
`346674de-1837-4d21-a234-2e61a85a5701`. Повторный запуск не создаёт дубликаты
и не перезаписывает изменённые данные или признак публикации.
Команда разрешена только для SQLite в development/test.

После регистрации и входа откройте `/labs`, затем `/labs/{lab_id}` в Swagger.
Без seed-команды свежая база возвращает пустой каталог.
Пример — комбинационная логика И с незавершённым шаблоном Verilog-2001.
Это материал для проверки API, не согласованная лабораторная курса.
Интерфейс `student_top` предварительный согласно контракту стенда.
Приём кода, запуск на ПЛИС и mock-проверка в этот модуль не входят.

## Проверки

```bash
ruff check .
pytest -q
```

Тесты каталога используют временные SQLite-файлы: проверяют сессии, обе роли,
скрытие неопубликованных работ, поля ответов, страницы, ошибки, повторный seed,
сохранение данных после перезапуска и обновление существующей базы.
Существующие PostgreSQL-тесты требуют `TEST_DATABASE_URL`; локально без этой
переменной они пропускаются, а в настроенном CI запускаются отдельно от SQLite.
