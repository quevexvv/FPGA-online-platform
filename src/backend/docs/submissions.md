# Решения студентов

Модуль сохраняет исходный код решения опубликованной лабораторной и позволяет
пользователю читать только свои отправки. Код хранится как текст: компиляция,
проверка Verilog, очередь и запуск на ПЛИС пока не выполняются. Ответ `201` означает
сохранение решения, а не успешную проверку лабораторной. Статуса проверки в ответе нет.

## Маршруты

Все маршруты требуют действующей cookie-сессии. Ответы, включая ошибки доступа
и валидации, содержат `Cache-Control: no-store`.

| Метод и путь | Результат |
| --- | --- |
| `POST /labs/{lab_id}/submissions` | Сохранить новую отправку; `201` и заголовок `Location` |
| `GET /labs/{lab_id}/submissions?limit=20&offset=0` | Список своих отправок без исходников |
| `GET /submissions/{submission_id}` | Своя отправка с исходником |

POST доступен только студенту и требует заголовка `X-CSRF-Token`. Токен возвращается
при входе, его также можно получить через `GET /auth/csrf`. Проверка `Origin`
использует те же правила, что и выход из аккаунта; подробности в
[authentication.md](authentication.md).

Тело POST содержит ровно одно поле:

```json
{"source_code": "module student_top;\nendmodule\n"}
```

Владелец определяется по сессии, лабораторная — по пути запроса.
Передавать `user_id`, `lab_id`, `test_set`, статус и другие дополнительные поля нельзя.
Пустой код, строка из пробелов, NUL и некорректный Unicode отклоняются.
Исходник сохраняется без удаления пробелов и изменения переводов строк.

Текущий предварительный лимит исходника — **64 КиБ в UTF-8** (`65 536` байт).
Это ограничение поля после разбора JSON, а не лимит всего HTTP-запроса.
Перед промышленным развёртыванием лимит тела запроса следует задать отдельно.
Размер исходника можно пересмотреть после согласования лабораторных с командой.

POST и элементы списка возвращают `id`, `lab_id`, `created_at` (UTC).
Детальный GET дополнительно возвращает `source_code`.
Список упорядочен от новых отправок к старым: `created_at DESC, id DESC`.
`limit` — от 1 до 100, `offset` — неотрицательное число.
При появлении новых отправок между запросами страницы с offset могут сместиться.

Каждый POST создаёт отдельную запись, даже при одинаковом исходнике.
Автоматический повтор после потери ответа может создать вторую отправку:
идемпотентность пока не реализована. Изменение и удаление отправок через API отсутствуют.

## Доступ и ошибки

| Код | Причина |
| --- | --- |
| `401` | Нет действующей сессии, сессия истекла или пользователь отключён |
| `403` | POST от преподавателя, неверный CSRF-токен или запрещённый Origin |
| `404` | POST в отсутствующую/неопубликованную лабораторную; GET чужой/несуществующей отправки |
| `422` | Неверный UUID, параметры страницы или тело запроса |

Чужая и несуществующая отправки имеют одинаковый ответ `404`.
Преподаватель не получает доступ к чужим решениям; преподавательский просмотр
будет отдельной функцией с проверкой групп и назначений.

Снятие лабораторной с публикации блокирует новые отправки, но сохраняет доступ
владельца к его истории. Список для неизвестного UUID лабораторной возвращает `[]`.
Ошибки валидации не возвращают введённый исходник в теле ошибки.

## Хранение

Миграция `0004_create_submissions` добавляет таблицу `submissions`: UUID отправки,
UUID пользователя, UUID лабораторной, исходник и дату создания. Внешние ключи
запрещают физическое удаление пользователя или лабораторной, пока на них ссылается
история. Индексы поддерживают выборку личной истории и ссылки на лабораторные.
При локальном запуске SQLite миграция применяется существующим механизмом старта.
Откат до `0003_create_labs` удаляет отправки; пользователи, сессии и лабораторные остаются.

## Проверка через Swagger

1. Запустить SQLite-приложение по инструкции в [laboratories.md](laboratories.md),
   при необходимости создать учебную лабораторную командой seed из той инструкции.
2. Открыть `/docs`, зарегистрироваться и войти через маршруты `auth`.
3. Вызвать `GET /labs`, скопировать UUID опубликованной лабораторной.
4. Получить CSRF-токен через `GET /auth/csrf` и передать его в POST решения.
5. Проверить `201`, затем список отправок и детальный GET по возвращённому UUID.
6. Войти другим аккаунтом: список должен быть пустым, детальный GET — вернуть `404`.

Автоматические проверки находятся в `tests/test_submissions.py`:
сессии, CSRF, роли, изоляция пользователей, границы размера, точное сохранение текста,
пагинация, перезапуск приложения и миграции. Локальный запуск: `python -m pytest -q`.
Интеграционная проверка PostgreSQL использует существующий CI и пропускается локально,
если `TEST_DATABASE_URL` не задан; настройка PostgreSQL для этой задачи не требуется.
