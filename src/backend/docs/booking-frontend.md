# Бронирование и проверка решений. Контракт для фронтенда

Сервер использует cookie сессии. Для fetch указывайте `credentials: 'include'`. Для POST, PUT, PATCH и DELETE с авторизацией отправляйте `X-CSRF-Token` из ответа входа. После перезагрузки страницы получить токен можно через `GET /auth/csrf`. Актуальные типы и проверку запросов предоставляет Swagger по адресу `/docs`.

## Бронь

| Запрос | Ответ и поведение |
| --- | --- |
| `GET /bookings/slots?date=2026-11-27&lab_id=<uuid>` | Массив свободных промежутков за календарный день в Томске. В каждом есть slot_id, starts_at, ends_at и available. lab_id необязателен. С ним сервер учитывает дедлайн, порядок и минимальную длительность. |
| `POST /bookings` | Принимает lab_id, starts_at, ends_at и необязательный slot_id. Ответ 201 содержит booking_id, lab_id, starts_at, ends_at, mine и state. |
| `GET /bookings/me?limit=20&offset=0` | Свои брони, начиная с наиболее поздней даты начала. Возможные состояния — reserved, active, cancelled, no_show, finished. |
| `DELETE /bookings/{booking_id}` | Отмена собственной брони до начала. Возвращает обновлённую запись. |
| `POST /bookings/{booking_id}/check-in` | Отметить приход в пределах интервала. Первая принятая отправка тоже отмечает приход. |
| `PUT /labs/{lab_id}/policy` | Преподаватель сохраняет полную настройку min_minutes, max_minutes, position, deadline. По умолчанию 5–60 минут, position=0 и deadline=null. |

Пример тела для создания брони (подставьте актуальный lab_id и свободные даты):

```json
{"lab_id":"b5f43be0-3f30-44b4-b891-721389962129","starts_at":"2026-11-27T15:23:00+07:00","ends_at":"2026-11-27T15:45:00+07:00"}
```

Промежуток можно сократить до разрешённой длительности. Если слот успели занять, сервер вернёт 409. Перезагрузите слоты. При выходе студента со страницы бронь сохраняется до конца интервала. Через 15 минут без явки остаток освобождается автоматически. Для короткой брони это происходит в момент её окончания. После отмены или неявки можно оформить новую бронь. Иначе новую можно создать после конца предыдущей. Студент может отправить несколько решений за свою сессию.

## Статус стенда и таймер

`GET /board/status` возвращает `state` (free, busy, unavailable), `current_session`, `session_ends_at`, `released_at`, `updated_at` и `server_time`. Сведения о чужой сессии включают интервал и состояние, идентификаторы владельца и его лабораторной скрыты. При отсутствии сессии current_session и session_ends_at равны null.

Таймер считает до session_ends_at по серверному времени. Если таймер дошёл до нуля, а ответ всё ещё busy, покажите «Проверка завершается» и продолжайте опрос. released_at — время, когда обработчик подтвердил освобождение после занятости. Заранее оно неизвестно. Если стенд занят, недоступен или освобождение ещё не наблюдалось, значение равно null. Для первого свободного состояния допустимы free и released_at=null.

Worker с учётной записью оператора проверяет блокировку стенда, настроенный UART и присутствие Cyclone V в нужной цепочке jtagconfig. Без свежего сигнала (90 секунд), при ошибке опроса или без рабочей конфигурации API вернёт unavailable. Успех /health сам по себе не подтверждает связь с платой.

## История, лабораторные и журналы

- `GET /submissions?limit=20&offset=0` возвращает свои отправки по всем лабораторным от новых к старым. В записи id, lab_id, lab_title, created_at, run_state, result_status, elapsed_seconds и счётчики open_passed/open_total, total_passed/total_tests. Для страниц limit от 1 до 100.
- `GET /labs` и `GET /labs/{id}` включают deadline, position, status, is_locked и blocked_reason. Статус студента — not_started, in_progress или passed. Причина блокировки — deadline, previous_lab либо null. Для положительных номеров сначала сдаются все опубликованные работы с меньшим номером. Position=0 означает независимую работу. Пройденной считается подтверждённая успешная аппаратная попытка.
- После `POST /labs/{id}/submissions` используйте `GET /submissions/{id}/run` для статуса. Фоновый worker забирает попытки сам. Диспетчер повторно сверяет границу после подготовки HDL. Ожидающая просроченная попытка получает finished/window_closed. Уже принятая диспетчером завершается штатно.
- `GET /submissions/{id}/logs` возвращает run_id, build, program и error. До появления журнала его значение null. Во время работы обновляйте вместе с /run, например раз в 3 секунды, после завершения выполните последний запрос. Доступен хвост до 16 КиБ исходного журнала каждого этапа, читаемый как обычный текст. При ошибке error содержит code и message. Сохранённые журналы остаются в БД после удаления файлов стенда. Для старых проверок без сохранённой копии поле может быть null. Для чужой отправки ответ 404.

## Профиль, ошибки и часы

- `PATCH /auth/me` с JSON `{"group":"8К51Т13"}` меняет группу текущего студента. `{"group":null}` очищает её. Ответ 200 возвращает профиль пользователя.
- Ошибки бизнес-правил имеют форму `{"detail":"сообщение"}`. Ошибки типа или структуры входных данных имеют код 422 и массив detail с loc, msg и type. Нарушение лимита длительности тоже возвращает 422, но detail — строка. 401 означает истёкшую или отсутствующую сессию: показать вход. 403 — неверный CSRF, Origin или роль. 404 — объект не найден или закрыт для пользователя. 409 — конфликт брони, срока или порядка лабораторных.
- `GET /health` без входа проверяет, отвечает ли сервер. `GET /health/db` проверяет соединение с БД и возвращает 503, если БД недоступна.
- Дата календаря — Asia/Tomsk (UTC+7). Для брони и дедлайна передавайте ISO 8601 со смещением либо Z. Ответы с моментами времени нормализованы к UTC. Для отображения переводите их в Asia/Tomsk.

## Локальная демонстрация

Из src/backend в Python-окружении проекта:

```bash
export DATABASE_URL=sqlite:///./fpga-booking-demo.sqlite3
python -m alembic upgrade head
python -m app.modules.bookings.demo --bindings ./demo-bindings.json
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

При первом запуске демо выведет локальные учётные записи студента и преподавателя и их случайные пароли. Повторный запуск сохраняет существующие записи. В Swagger войдите через /auth/login. Создайте бронь на первую работу и проверьте расписание со второго аккаунта. Подготовлены две лабораторные с примерами решений из src/fpga/examples/combinational и src/fpga/examples/counter. Для показа очереди запустите worker по инструкции в fpga-runner.md с тем же DATABASE_URL, файлом demo-bindings.json и настройками стенда. При демонстрации без оборудования API брони, профиль и каталог работают, статус платы будет unavailable.
