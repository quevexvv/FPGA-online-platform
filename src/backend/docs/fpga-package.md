# Подготовка пакета решения для ПЛИС

Первый шаг задачи YouGile [ONL-92 — бэкенд-клиент диспетчера](https://ru.yougile.com/team/12dc762c0d5a/#ONL-92).
Команда читает уже сохранённую отправку по `run_id` и формирует два файла:
`manifest.json` и `src/student_top.v`. Формат соответствует
[контракту стенда](../../../docs/contract.md).

Это локальная подготовка к передаче. Команда не вызывает диспетчер, не делает
SSH/SFTP-запросов, не запускает HDL, не меняет состояние БД и не создаёт новую попытку.
Статус остаётся `queued`. Пакет не содержит профиля студента, cookie, пароля,
ожидаемых ответов тестов или других данных пользователя.

## Доверенная привязка лабораторных

Оператор/разработчик задаёт JSON-файл привязок: UUID лабораторной → её тип и
установленный на стенде набор тестов. Пример структуры (UUID заменить на реальный
ID лабораторной счётчика, соответствующей `counter-v1`):

```json
{
  "schema_version": 1,
  "labs": {
    "00000000-0000-0000-0000-000000000001": {
      "kind": "sequential",
      "test_set": "counter-v1"
    }
  }
}
```

Этот файл не принимается от студента и не передаётся через HTTP. Для одной
лабораторной выбирается один набор. Неизвестный ID, неверный тип лабораторной,
путь или команда вместо имени test_set приводят к ошибке. Наличие набора на стенде
и соответствие его ожидаемых ответов условию проверяются при согласовании с
интегратором и при приёме диспетчером: пакетировщик не имеет доступа к стенду.

У существующей учебной seed-лабораторной условие логического И. Нельзя автоматически
назначать ей `combinational-v1` только по типу схемы: смысл этих тестов может
отличаться. До согласования набора оставлять её без привязки.

## Локальная команда

После запуска приложения и создания отправки получить `run_id` через
`GET /submissions/{submission_id}/run`. Нужен ID попытки, не отправки/лабораторной.
Сохранить согласованную конфигурацию в `bindings.json` вне репозитория, создать
приватную папку подготовки вне каталога стенда и выполнить из `src/backend`:

```bash
mkdir -m 700 /tmp/fpga-staging
DATABASE_URL=sqlite:///./fpga-local.sqlite3 python -m app.integrations.fpga.package \
  --run-id UUID_ПОПЫТКИ \
  --bindings /path/to/bindings.json \
  --output-dir /tmp/fpga-staging
```

Получится `/tmp/fpga-staging/<run_id>/manifest.json` и
`/tmp/fpga-staging/<run_id>/src/student_top.v`. Корневая папка должна существовать
и быть доступна только доверенному процессу/оператору. Новый каталог имеет права
700. Исходник записывается в UTF-8 без изменения переводов строк и пробелов.
`top=student_top` и путь исходника фиксированы сервером, а не выбираются студентом.

Повторная команда для существующего каталога останавливается без перезаписи,
включая случай симлинка. При ошибке записи удаляется только новый незавершённый
пакет этой команды. После аварийного завершения процесса частичный каталог может
остаться; его нужно проверить до дальнейшей работы, автоматически он не используется.

Не направлять `--output-dir` прямо в `incoming` диспетчера: публикация/доставка
будет отдельным шагом. Во время подготовки каталог ещё не является готовым
заданием для отправки. Передавать можно лишь после успешного завершения команды.
Не добавлять созданные пакеты с пользовательским кодом в Git.

Принимаются только сохранённые попытки hardware без снимка статуса и результата.
Запущенные/завершённые попытки не перепаковываются. Команда не резервирует задание
для worker: до появления блокировок её использовать вручную без параллельного
запуска той же попытки. Для автоматической очереди понадобится фиксировать
привязку test_set и видимость тестов на момент создания попытки.

## Проверка и следующие этапы

`tests/test_fpga_package.py` проверяет формат, точное сохранение исходника,
отсутствие изменений БД, ошибки конфигурации, повторный экспорт, симлинк и сбой записи.
На Linux с jq отдельно проверяется, что настоящий `fpga-dispatch` принимает пакет
в изолированной временной папке при `FPGA_DISPATCH_LAUNCH=manual`, mode=mock.
Это проверка совместимости формата, без компиляции HDL, запуска платы или записи
mock-результата как аппаратной сдачи. На macOS этот тест пропускается.
